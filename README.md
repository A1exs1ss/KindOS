## KindOS (Kindrel Kernel)

KindOS — это экспериментальная микроядерная операционная система, написанная на чистом ассемблере (NASM x86). 
Но это не просто «еще одна ОС». Это фундамент для глобальной концепции — «Бессмертный Windows»

## Концепция «Бессмертный Windows»

Главная цель: Сделать Windows бессмертной — создать ОС, которая спасает систему, когда та падает, и не даёт пользователю потерять данные.

Как это работает:
1.  watchdog:  На уровне загрузчика есть watchdog, он проверяет Windows на BSOD. В случае успешного запуска - счётчик сбрасывается. При счётчике: "2" - watchdog предлагает выбор пользователю: "Перейти в KindOS или нет" 
1.1. Безопасность: Весь код будет доступен в GitHub. Watchdog просто следит за состоянием Windows.
2.  Своя среда восстановления: Вместо пугающего синего экрана от WinRE, пользователь попадает в понятную ОС. Она будет в теневом секторе, поэтому флешка не пригодится. Разумеется тут будут игры, интернет и т.д. Пока реализована только графика, но это временно...
3. Neuro-CMD: Внутри работает ИИ-агент. Он чинит Windows изнутри через консоль, пока пользователь отвлечён, имеет доступ в интернет и может генерировать новые команды. 
3.1. Безопасность: Все сгенерированные команды от ИИ проходят обязательный dry-run (проверку без выполнения) и фильтрацию по белому списку (whitelist). Полный лог действий ИИ всегда доступен пользователю и хранится в базе данных. Также ИИ имеет доступ к бекапам, на случай ошибки. Перед работой он создаёт точку отката, которая удаляется при полном выполнении задачи
4.  Философия Kind: Никакого вредоносного кода или скрытого контроля. ИИ действует открыто, сообщает о своих действиях и всегда оставляет выбор за пользователем. А ОС пытается лишь успокоить пользователя. 
5.  Кстати, KindOS не изменяет файлы Windows и не распространяет проприетарные компоненты Microsoft

## Архитектура
Я считаю, что сложность - враг надёжности. Поэтому архитектура строится по принципу: сначала стабильность, потом - функции.

1.  Микроядро (Kindrel): ~2k строк на NASM. Управляет памятью, прерываниями и графикой. Обеспечивает переход в Protected Mode (PM), работу IDT/PIC и экспорт системных вызовов.
2.  Графическая подсистема: Собственный оконный менеджер с двойной буферизацией. Окна перетаскиваются, работает обработка мыши и клавиатуры.
3.  Модульность: Система состоит из независимых модулей (Stage 5, Stage 6), которые общаются с ядром через строгий API (Export Table).
4.  Экономия ресурсов: ОС спроектирована для работы на 64 МБ оперативной памяти, чтобы она могла запуститься в критической ситуации

## Что готово (На данный момент выполнено ~10%)

1.   Ядро (Kindrel): Загрузка в Protected Mode, обработка прерываний (PIT, клавиатура, мышь).
2.  Оконный менеджер: Работающие окна, перетаскивание (drag-and-drop), контекстное меню, кнопка закрытия.
3.  Графика: Идеальный курсор, собственные функции рисования (геометрические фигуры, 256 цветов и ещё шрифты 8x8).
4.  Облик-Терминал: Работающее окно терминала (заготовка для Neuro-CMD).
5.  Stage 5/6: Драйвер памяти и файловый менеджер всё ещё в разработке.

## Немного фактов

1.  2 месяца работы. Инструменты: обычный Блокнот Windows (без IDE и автодополнения) и NASM в командной строке.
2.  80+ тестов на реальном железе: проект проверялся на разных конфигурациях (через образы), а не только в виртуалке. Каждый новый образ — новая попытка.
3.  Приручение Triple Fault: первая встреча с ним заняла 3 дня отладки. Сейчас причина находится менее чем за час.
4.   ИИ в чате: код генерировался с помощью ИИ в обычном чате, затем вручную копировался в файлы и отлаживался. Это доказывает, что даже без продвинутых инструментов можно создать работающую ОС.
5.   Код генерировала Нейросеть, потом вручную проверялся  и отлаживался. ИИ дал возможность в разработке ОС, но не стал решать все проблемы разом.
